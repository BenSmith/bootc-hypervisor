# Every vm_/VM_-prefixed public symbol defined in lib/, classified.
#
# THE PREFIX IS A CLAIM, AND FOR MOST OF THESE IT WAS FALSE. The egress stack,
# the CA, hostname policy, inspection records, the nft constants and uid
# addressing all lived in vm-named symbols and were used by the container path
# just as much. A reader who trusts the prefix concludes a shared thing is the
# VM's; someone editing on that belief changes container behaviour without
# knowing it.
#
# HOW A LINE IS DECIDED: BY CONSUMER, NEVER BY NAME. A symbol is KEEP when
# every consumer outside its own module is on a path only a VM takes, and
# RENAME otherwise. Two consequences that are easy to get backwards:
#
#   * A container_ TWIN OUTRANKS ALL OF THIS. If container_<stem> exists,
#     the prefix is not a leftover -- it is what tells two substrate variants
#     of one operation apart, and stripping one of the pair leaves
#     `uses_inspect` beside `container_uses_inspect`, reading as a generic and
#     its specialisation. That is this file's own defect with the sign
#     flipped. Six symbols were renamed and reverted before anyone noticed, so
#     the ratchet now FAILS on a RENAME verdict for any symbol with a twin
#     rather than leaving the rule to a reader.
#   * A vm-named FILE is not evidence either. generators/workload-generate
#     called gen_vm's inspector and broker unit generators for CONTAINERS --
#     the arming helper was the only substrate-specific value -- so what
#     those three functions touch is shared no matter which file it is
#     reached from. (They are gen_egress's now, and named accordingly.)
#   * Tests are not evidence. A symbol used only by a vm-named test module is
#     classified by where it is DEFINED, because a test name follows the code
#     it was written against and would just restate the prefix.
#   * A symbol with NO consumer outside its own module has no consumer
#     evidence at all, so it falls back to the module -- and a module is
#     VM-only only when every file that IMPORTS it is. That test is what
#     separates vm_ptp, imported by ensure_vm alone, from vm_clock, which
#     egress_mint and the substrate-shared inspect listener both import.
#
# WHAT THIS FILE IS FOR. tests/test_vm_prefix_ratchet.py asserts that what the
# tree actually defines equals RENAME + KEEP exactly, in both directions. So
# renaming a symbol forces its line to be deleted in the same commit, and a
# new vm-prefixed symbol fails the suite until someone classifies it. RENAME
# only shrinks, and its diff is the record of the work.
#
# THE HONEST WEAKNESS: nothing mechanical stops a line being moved from RENAME
# to KEEP instead of the work being done. That is a review question, and the
# diff is what makes it visible.
#
# The two constants whose VALUE is pinned by hosts already running --
# workload_addr.INSPECT_LISTENER_BIN and config_parser.SOCKET_DIR -- were renamed
# last and deliberately, with the values asserted before and after. The rule
# outlives the rename: change either constant's spelling freely, never what it
# holds. TestTheValuePinnedConstants pins both strings.
